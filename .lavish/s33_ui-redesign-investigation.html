The brand itself is not the problem. s25 “Flight Deck” is a real, documented system (five-primitive kit, type-voice rule, chart-paper light theme, reduced-motion stills, Playwright baselines — AGENTS.md:262-300). 03 · the decision

Reuse strategy — decided: Option B, full shadcn/ui migration

Your call (annotated in review): “move to as many libraries as possible and future-proof the app” — maximum reuse wins over migration cost. This rewrites the doctrine at AGENTS.md:736-741 (hand-rolled CSS, no Tailwind) — that edit is now an explicit P0 deliverable, not a side effect. Options A (headless + tokens) and C (cosmetic pass) were considered and rejected: both keep the agent hand-building more of the stack than B does.

Chosen

Option B · Tailwind v4 + shadcn/ui + tweakcn

shadcn components are copy-in owned code on Radix primitives; every coding agent is deeply fluent in this stack, and the animated-component ecosystem (Magic UI, Aceternity, React Bits, 21st.dev registry) plugs straight in. The default-look risk is handled by encoding the Flight Deck palette as a custom tweakcn theme — navy/amber/JetBrains-Mono instrument voice, not zinc-and-white.

max reuseagent-fluent stackdoctrine rewrite in P0migrate surface-by-surface

Migration architecture (how B lands without breaking the app)

coexistence — old CSS and Tailwind side by side

  • Tailwind v4 via Vite plugin; import order puts existing styles.css in a cascade @layer above preflight so the reset can’t wreck unmigrated surfaces — preflight stays off/scoped until P3 completes.
  • Token bridge: tweakcn theme variables (--background --primary --radius…) are aliased from the existing Flight Deck tokens, not duplicated — one palette, two naming systems during migration; charts/tokens.ts and visx keep working untouched.
  • Surface-by-surface flips: each PR converts one surface to shadcn components and deletes its legacy CSS block; the 1,561-line stylesheet shrinks to tokens + login scene + report-engine cards.
  • Report engine fenced: its three card classes get restyled once with the new tokens but stay plain CSS — PNG export must render identically outside the app.

what shadcn gives us per pain point

  • Native selects → shadcn Select/Combobox everywhere (Explore, SQL chart builder, Admin filters).
  • Button/card/input zoo → one Button with variants, Card, Input, Tabs, Table, Dialog, Tooltip, DropdownMenu, Command (replaces the hand-rolled ⌘K palette).
  • Sidebar: shadcn ships a first-class Sidebar block with an icon-collapsible mode — the hover-expand rail in §6 becomes configuration, not custom code.
  • Icons: lucide-react (shadcn default) replaces emoji glyphs; the hand-drawn brand icons (plane, reticle) stay.
  • Login flair: Magic UI Globe (cobe) and Dotted Map are literally pre-built shadcn-registry components — V1/V2 below become install-and-style.
